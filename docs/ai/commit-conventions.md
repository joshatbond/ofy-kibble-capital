# Commit Conventions

Use semantic commit messages (Conventional Commits) for all repository commits.

## Format

`<type>(optional-scope): <summary>`

Examples:

- `feat(kibble): add paystub list route shell`
- `fix(convex): index ledger entries by classroom and student`
- `docs(ai): add architecture foundation from kanto template`

## Allowed types

- `feat`: new functionality
- `fix`: bug fixes or regressions
- `refactor`: structural improvements without behavior changes
- `docs`: documentation updates
- `test`: test additions or updates
- `build`: tooling/build/dependency changes
- `ci`: CI workflow updates
- `chore`: maintenance tasks that do not fit other types

## Scope guidance

Use a short scope when it improves clarity. Common scopes for this project:

- `kibble` — Kibble Capital routes and UI
- `pawket` — PawKet Exchange routes and UI
- `admin` — teacher administration hub
- `convex` — schema, functions, backend
- `auth` — Convex Auth, invitations, tenants, authz
- `router` — TanStack Router / routes
- `ui` — shared components and design system
- `react` — component structure, state placement, colocation (see [`react.md`](react.md))
- `pwa` — manifests, service worker, install surfaces
- `netlify` — deploy config and build pipeline
- `deps` — dependency updates
- `ai` — agent docs and contributor guidance

## Subject line rules

- Imperative mood: "add", "update", "remove", "fix"
- Keep concise and specific
- Avoid trailing punctuation
- Never append tool attribution/signature lines
- Forbidden examples: `Made with: Cursor`, `Generated by <tool>`, `Co-Authored-By: <tool>`
- Remove any such lines from draft messages before commit

## Body guidance

Add a body when context is non-obvious:

- Why the change was needed
- Notable tradeoffs or follow-up work

Example:

```
feat(auth): add invitation accept mutation

Mirrors ms-engage-v2 invite flow: validate email match, attach member to
tenant, reject expired tokens.
```
